## 6. POS Apotik Flutter untuk Windows dan Android

Aplikasi berada di `apps/pos-flutter`. Satu source membangun produk retail,
Inventory Sales, dan Apotik melalui mode/flavor berbeda. CI sudah diubah
menjadi matrix per produk agar cache/build satu produk tidak mencemari produk
lain.

Khusus mode Apotik:

- login memakai username/email dan kata sandi server;
- kode tenant sudah dihapus dari formulir; tenant ditentukan server dari akun
  dan membership yang unik;
- katalog, outlet, terminal/register, shift, metode pembayaran, dan transaksi
  dibaca/ditulis ke server tenant;
- jika belum ada shift aktif, pengguna diarahkan ke layar pembukaan shift;
- tersedia workspace OTC, resep, racikan, produksi farmasi, pembelian/PBF,
  penerimaan, master produk, stok opname, riwayat, retur, void, perangkat,
  sinkronisasi, buka shift, dan tutup shift;
- Android memakai application ID `id.emedik.pos_apotik`, sehingga dapat
  dipasang berdampingan dengan POS retail;
- pembaruan diperiksa saat aplikasi dibuka, berkala, dan manual. Metadata
  dipisahkan per platform supaya versi Windows tidak memaksa Android mengunduh
  berkas yang salah.

Berkas utama:

- `apps/pos-flutter/lib/main.dart`
- `apps/pos-flutter/lib/api/pos_api.dart`
- `apps/pos-flutter/lib/layar/layar_kasir.dart`

## 7. Unduhan dan pembaruan

Landing `apotik.emedik.id` memakai endpoint publik berikut:

- Windows: `/api/v1/update/pos-apotik-windows.exe`
- Android: `/api/v1/update/pos-apotik-android.apk`
- Metadata aplikasi: `/update/apotik/latest?platform=windows|android`

Apache mem-proxy `/update/` ke API. Controller unduhan berada di
`apps/api/src/modules/public/pos-update.controller.ts`. `deploy/update.sh`
menyalin artefak dari `artifacts/apotik-release` dan, bila
`POS_RELEASE_GITHUB_TOKEN` atau `GITHUB_TOKEN` tersedia di server, menarik
asset rilis GitHub ke `/opt/ebisnis/updates/pos` pada setiap eksekusi,
termasuk saat source tidak berubah.

Keadaan artefak saat serah-terima:

| Kanal | Windows | Android | Status |
| --- | --- | --- | --- |
| Stable `pos-v0.1.18` | `emedik-pos-apotik-0.1.18-windows.exe` | tidak ada pada rilis stable | Windows produksi tersedia |
| Pratinjau `pos-v0.1.17` | `emedik-pos-apotik-0.1.17-windows.exe` | `emedik-pos-apotik-0.1.17.apk` | UAT/pratinjau, tidak ditarik otomatis oleh deploy stable |
| Artefak di repository | Windows sampai `0.1.16` | Android sampai `0.1.12` | Fallback untuk server tanpa token release |

Karena `update.sh` hanya menarik rilis yang bukan draft dan bukan prerelease,
paket `0.1.17` tidak otomatis menjadi unduhan publik. Server bertoken akan
menarik installer Windows stable `0.1.18`. Alias Android produksi akan tetap
memilih APK terbaru yang benar-benar ada pada folder update server, umumnya
`0.1.12` dari repository sampai rilis Android stable yang signed diterbitkan.

Android signing produksi belum boleh dianggap selesai. Workflow memerlukan:

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_STORE_PASSWORD`
- `ANDROID_KEY_PASSWORD`
- `ANDROID_KEY_ALIAS`

Build debug boleh dipakai untuk verifikasi manual, tetapi tidak boleh menjadi
pembaruan produksi karena Android menolak upgrade dengan kunci yang berbeda.

## 9. Integrasi Sales/Inventory yang dipakai ulang

Implementasi Apotik memakai fondasi Inventory/Sales untuk fungsi yang memang
sama: master produk, supplier/PBF, purchase order, penerimaan, batch, stok,
harga, pelanggan, penjualan, pembayaran, kas, piutang/hutang, jurnal, audit,
dan laporan. Lapisan Apotik menambahkan aturan klinis seperti resep, racikan,
produksi farmasi, FEFO, kedaluwarsa, high-alert, controlled drug, konseling,
dan persetujuan apoteker.

Perbaikan integritas terbaru pada fondasi bersama mencakup checkout luring
idempoten, freeze stok opname, pembatasan approval/void, masking data bank,
penjagaan purge salesperson, reversal payable penerimaan barang, dan moving
average cost. Rincian serta gap turunannya ada pada ringkasan sesi lintas
Inventory yang ditautkan di bagian 1.

## 10. Deploy dan perbaikan migrasi

Kegagalan migrasi tenant yang pernah muncul pada V044/V045 telah ditangani
melalui perbaikan migrasi aman dan penyemaian shared actions. Jalur deploy juga
telah diperkuat dengan lock, self-reexec setelah pull, backup yang tidak
melewati batas proses shell, fetch tag paksa, pemeriksaan versi pnpm, dan
sinkronisasi artefak POS sebelum fast exit.

Server harus permanen berada pada branch `main`. Untuk pemindahan pertama:

```bash
sudo -u ebisnis git -C /opt/ebisnis/app fetch origin
sudo -u ebisnis git -C /opt/ebisnis/app checkout main
sudo -u ebisnis git -C /opt/ebisnis/app pull --ff-only origin main
sudo bash /opt/ebisnis/app/deploy/update.sh
```

Setelah itu cukup:

```bash
sudo bash /opt/ebisnis/app/deploy/update.sh
```

Push ke GitHub tidak sama dengan deploy produksi. URL produksi baru menjadi
bukti setelah perintah deploy selesai tanpa rollback dan smoke test lolos.

## 11. Memulai di komputer baru

```powershell
git clone https://github.com/Zishof/eBisnis.git C:\opt\eBisnisGithub-ekoperasi
Set-Location C:\opt\eBisnisGithub-ekoperasi
git checkout main
git pull --ff-only origin main
corepack enable
corepack prepare pnpm@9.15.4 --activate
pnpm install --frozen-lockfile
pnpm --filter @ebisnis/api build
pnpm --filter @ebisnis/web build
Set-Location apps\pos-flutter
flutter pub get
flutter analyze
flutter test
```

Build Windows Apotik:

```powershell
flutter build windows --release --dart-define=POS_MODE=apotik --dart-define=POS_APOTIK=true --dart-define=POS_API_BASE=https://apotik.emedik.id/api/v1/
```

Build Android Apotik untuk UAT lokal:

```powershell
flutter build apk --release --flavor apotik --dart-define=POS_MODE=apotik --dart-define=POS_APOTIK=true --dart-define=POS_API_BASE=https://apotik.emedik.id/api/v1/
```

Untuk rilis Android produksi, pulihkan keystore dan `android/key.properties`
melalui secret yang aman. Jangan commit keystore, password, token, atau `.env`.

Konfigurasi yang tidak berada di Git dan perlu dipulihkan terpisah:

- `.env` server;
- secret enkripsi dan database;
- token sinkronisasi GitHub Release pada server;
- keystore/signing Android;
- credential DNS/Cloudflare dan akses server;
- akun tenant uji yang sah.
