## Catatan reproduktibilitas

`pnpm` global pada mesin adalah 11.16.0, sedangkan proyek mengunci 9.15.4. Percobaan awal dengan versi global menghasilkan virtual store yang tidak konsisten (termasuk kegagalan ESM `htmlparser2` dan mismatch biner esbuild). Baseline otoritatif di atas dijalankan setelah clean install melalui `corepack pnpm`; folder dependency lama hanya disingkirkan sebagai backup lokal dan tidak masuk Git.

E2E pertama memakai rate-limit pengembangan dan menghasilkan 63 pass, 3 timeout login demo mobile, 15 skip, serta 7 tidak dijalankan. Workflow E2E resmi menetapkan `THROTTLE_DEFAULT_LIMIT=5000` dan `THROTTLE_AUTH_LIMIT=200`. Setelah API commit baseline dijalankan pada port terpisah dengan nilai resmi tersebut, pengulangan lulus 73/73 test yang aktif. Lima belas test POS pada project `chromium-mobile` di-skip oleh suite, sehingga hasil ini **bukan** bukti Android POS.

API dan Vite baseline dijalankan pada port terpisah agar service pengguna di port 3000 tidak dihentikan. Fixture E2E dibuat sementara lalu berhasil dibersihkan. Semua proses baseline tambahan juga dihentikan.

## Gap yang tetap terbuka

- Tiga belas golden Flutter harus ditinjau visual; golden tidak diperbarui otomatis.
- PASS source/analyze/widget tidak sama dengan UAT Windows atau Android fisik.
- Bukti API yang sudah ada tidak boleh menutup kolom Web, Windows, Android, offline, print/export, rekonsiliasi, atau business UAT.
- Lima belas test POS mobile yang di-skip perlu pengganti berupa widget/golden Android dan UAT perangkat sesuai tracker.

Status P0 pada dokumen ini adalah baseline tercatat, bukan deklarasi paritas UI 48/48.

## Tindak lanjut setelah baseline

Triase semua 13 diff membandingkan master dan hasil Windows serta mengonfirmasi
perbedaan rasterisasi font Skia lintas sistem operasi yang juga telah dicatat
pada `.github/workflows/perbarui-golden-pos.yml`. Golden Ubuntu tetap utuh.
Baseline Windows ditambahkan di `apps/pos-flutter/test/goldens/windows/`, lalu
`flutter analyze` lulus dan `flutter test` lulus 190/190 tanpa `--update-goldens`.
Hanya layar 20 dan 30 yang dinaikkan menjadi `AUTOMATED_PROVEN` untuk surface
Windows/view karena keduanya mempunyai golden workspace yang spesifik. Hasil
ini tetap bukan `DEVICE_UAT_PROVEN` dan tidak menutup Android.

Gap draft layar 30 kemudian dipindahkan dari `sessionStorage` ke IndexedDB.
Idempotency key dibuat sekali dan disimpan bersama draft sampai order sukses,
sehingga retry tidak lagi membuat identitas baru. Test adapter durable lulus,
tetapi registry tetap `SOURCE_IMPLEMENTED` untuk Web/create dan Web/offline:
belum ada bukti E2E bahwa browser ditutup/dibuka serta outbox mengirim ulang.

E2E portal kemudian membuktikan layar 20 dan 30 pada project Chromium desktop
dan mobile-browser: route hidup, autocomplete memakai listbox nyata, serta
draft layar 30 tersimpan ke IndexedDB. Empat test terfokus lulus. Karena itu
Web/view untuk layar 20 dan 30 naik menjadi `AUTOMATED_PROVEN`; Web/offline
tetap `SOURCE_IMPLEMENTED` sampai close/reopen dan retry outbox dibuktikan.
